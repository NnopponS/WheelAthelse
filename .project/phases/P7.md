# P7 physical capture and acceptance protocol

Updated: 2026-09-10.

## Current status

Source support for L/R plus optional chair-center C is complete for the maintained Windows/firmware release path. The specific XIAO center board was flashed and read back as **firmware 1.8.2**, role `C` / `0x43`, with the green identity behavior. A post-flash run reached 1,780.865 s before board removal; the final 1,750 s snapshot contained 179,290 samples with zero observed sequence, malformed, host-queue, firmware-queue, notification or FIFO loss/fault counters.

This is strong partial runtime evidence, **not final physical acceptance**. The final STOP acknowledgement, Windows Python-app record/QC/reopen/export sequence, and simultaneous L/R/C bench run were not completed before the hardware became unavailable. No new synchronized L/R/C + moving optical-reference athlete capture or coach sign-off exists.

## Sensor configuration

Baseline sensors:
- L wheel-hub IMU;
- R wheel-hub IMU.

Optional instrumentation:
- C chair-center/frame IMU (`0x43`);
- mounting contract: **+Z down toward the floor**;
- X/Y remain physical board axes until chair-forward/lateral orientation is physically measured.

XIAO C uses green identity/heartbeat; M5 C uses its yellow display identity. Error/retry indication remains higher priority than identity styling.

A third IMU is not an absolute position reference and must not be assumed to improve accuracy.

## P7A - Remaining center bench acceptance

When hardware returns:

1. re-enumerate and record the exact intended board identity before any flash/test;
2. read firmware version, role, configured sample rate and declared ranges/scales;
3. mount C with +Z down and verify static gravity direction and approximately 1 g magnitude after scale conversion;
4. document chair-forward and chair-lateral board axes;
5. verify green identity does not mask retry/error state;
6. connect L/R/C simultaneously and inspect sequence, replay/drop, queue, FIFO, transport and START acknowledgement state;
7. preserve pre/post clock observations and START mapping for all three streams;
8. record a complete L/R/C session from the Windows app, obtain final STOP acknowledgement, run QC, reopen it and export it;
9. verify C remains C in journal metadata/raw export and that L/R-only backward compatibility is unchanged.

This is hardware identity/orientation/timing/data-integrity acceptance, not trajectory-accuracy validation.

## P7B - Optical reference requirements

Reference captures must contain actual moving trajectories. For each C3D/reference file verify:
- intended moving markers are present;
- marker-to-wheel/chair mapping is documented;
- units and sample rate are known;
- residual/validity fields and dropout runs are reviewed;
- the complete maneuver is retained;
- IMU pairing is independently justified;
- a common event/time transform connects reference clock to L/R/C clocks.

Model-derived pseudo markers must never become ground-truth labels or scores.

## P7C - Capture matrix

For each fixed mounting/remount group collect representative:
- static before motion;
- forward acceleration/coast/braking;
- reverse;
- one-wheel arcs left/right;
- in-place pivots left/right;
- complete Slalom;
- 10x5/shuttle with documented turns/course;
- pause/restart;
- hard braking/turning where slip is plausible.

Repeat across days/remounts and multiple athletes/load/surface conditions as feasible. Keep all windows from one correlated trial/group together.

Log hardware identity, firmware hashes, ranges/scales, configured rate, mounting diagram, sequence/drop/replay/FIFO/transport faults, clock evidence, reference QA and operator/reviewer. Failed captures are retained with reasons.

## Split/freeze rules

Before examining candidate outcomes, assign each capture group to development/calibration, validation or final locked. Keep participant/day/session/remount together. Do not tune normalization, delay, geometry, calibration or model selection using the locked final data.

## Two-IMU vs three-IMU study

After capture QA passes:

1. freeze the L/R baseline and source/config hashes;
2. define a new explicit center-aware feature/input contract;
3. train using development groups only;
4. compare L/R and L/R/C on the same validation trials;
5. report per-maneuver improvements and regressions;
6. freeze one candidate before opening the final group.

Do not silently concatenate C into the legacy 12-channel model tensor.

## Evaluation package

For each intended trial report inclusion/exclusion reason, reference/timing provenance, initial-pose-aligned trajectory, ATE/RPE/path/endpoint metrics, wrapped/unwrapped heading, signed speed, yaw rate, turn timing, declared-bandwidth acceleration, coverage/failures and paired L/R-vs-L/R/C difference.

Protocol-specific constrained estimators require raw and constrained results separately.

For a two-hub control capture, center fields remain explicitly empty/`not_present`; never fabricate values.

## P7 conclusion

The next missing evidence is physical, not more source plumbing: finish the center bench/app acceptance and then capture synchronized L/R/C plus valid moving optical reference. Until that exists, C remains optional recorded instrumentation and current production model defaults remain L/R-only.
