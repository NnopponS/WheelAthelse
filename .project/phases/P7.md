# P7 capture protocol and acceptance ledger

## Current status

**Capture preparation is documented. No new physical recording, installed-app validation, Android/iOS device acceptance or athlete/coach sign-off was performed in this continuation.** Existing PC journals can exercise loading and offline review, but their saved affine mappings do not independently prove motion accuracy. This document is the next experimental work order, not a completed experiment.

Keep two existing wheel-hub IMUs. Do not add hardware, flash firmware, change raw data or install/release software under this work order. Any later device installation or firmware change needs separate authorization.

## Required roles and evidence

The capture operator records the performed maneuver and all failures. The optical-reference owner verifies moving wheel markers and reference quality. The data/model reviewer freezes group membership, checks clocks and evaluates the already frozen candidate. The athlete and coach decide whether time-local results and uncertainty are useful. One person may fill several roles, but each decision must have an owner and dated evidence.

## Pre-capture verification

Record a capture ID and the actual chair, load, tire state, surface and sensor mounting. Retain the inherited 0.30 m radius / 0.52 m hub spacing / zero-camber configuration unless measured values are explicitly approved for a separate calibration experiment. Keep the 0.04 m configured IMU offset and 0.066 m reflector offset distinct from track width. Photograph/diagram the axes and mounting without exposing unrelated people or documents.

Record each sensor's hardware identity, serial/device identifier, actual firmware build, accelerometer/gyro range, numeric scale advertised over BLE and configured sample rate. Preserve original raw counts and timestamps when the existing recording format supports them. A generic full-scale conversion and an LSM6DS3-specific sensitivity must not be mixed without verified provenance. The P2 quantization audit is a reason to inspect this, not authorization to multiply old data by a guessed factor.

Verify recording free space and actual selected L/R roles. Preserve start acknowledgment, sequence/replay/drop counters, pre/post clock observations and any firmware acquisition faults. A high-level GOOD status is not sufficient on its own. Save incomplete/failed captures with a reason rather than deleting them to improve coverage.

## Optical reference requirements

Export complete moving left and right wheel-marker trajectories, not a gait overlay or an empty POINT export. For every file verify marker names and their physical mapping, declared units, sample rate, residual validity, dropout runs, marker separation and duplicated fingerprints. Retain the original file unmodified. Do not fill a missing reference gap and later label it as an observed point.

The existing September POINT.USED=0 exports and static foot markers do not satisfy this requirement. A matching-looking filename does not establish the correct IMU/reference pair. Document the common event and timestamp transformation used to connect the reference clock to both wheel clocks, including uncertainty and the origin convention.

## Minimal maneuver coverage

Use the same nominal geometry and frozen model for comparisons. Include observed static intervals before and after motion; forward straight acceleration/coast/braking; deliberate reverse motion; both directions of a one-wheel arc; both in-place rotation directions; slalom; the precisely defined shuttle maneuver; and pause/restart sequences. Record the actual number and direction of turns rather than forcing a nominal 1800-degree target into calibration.

Repeat across multiple trials, days and remounts, and across athletes/load/surface conditions when practical. Keep all windows of a trial together and group correlated captures by participant/session/remount. The purpose is to reveal transfer errors, not merely produce many correlated sample windows.

## Split and freeze rules

Before candidate outcomes are inspected, create a manifest with capture ID, athlete/session/remount group, maneuver, paths and hashes, sensor/calibration identity, reference availability, clock evidence, and one role: calibration/development, validation or final-locked. Reserve an independent final group. No row may be omitted for a bad prediction; exclusions require a predeclared reference/input-quality reason.

Use development data for method diagnostics, validation for a single candidate decision, and the final group once for its locked evaluation. Historical July test IDs have already influenced earlier recipes and cannot serve as a pristine final group. Never normalize, tune scale, choose delay or select a winner using the locked final recordings.

## Evaluation package

For each intended trial retain original QA, inclusion/exclusion reason, timing provenance, reference support and all predictions/errors. Primary alignment is one declared initial pose, not a fitted trajectory rotation/scale or per-window resetting. Include full trajectory and time-local overlays, unwrapped and wrapped heading, endpoint error, path-length error, one-second relative position error, signed speed, yaw rate, defined turn-event timing and acceleration with the same derivative bandwidth for prediction and reference.

Report equal-trial/group summaries with counts and individual regressions. Thousands of correlated samples do not create thousands of independent experiments. With few independent groups, disclose uncertainty rather than presenting a confident sample-level bootstrap.

All numeric coaching targets in the original plan remain provisional discussion values. The coach must agree the final thresholds and acceptable per-maneuver regressions before final-test evaluation. No current software test establishes those thresholds have been met.

## Athlete/coach workflow acceptance

Use an approved build on the intended Windows/mobile device, in a separate authorized installation task. Open a real finalized recording, confirm athlete/trial/model identity and quality limitations, generate offline analysis, choose a time and locate its exact path point, select a time window, inspect speed/braking/turn quantities and compare repeats. Verify that an unavailable quantity is understandable rather than looking like zero. In particular, the current mobile XY-only model must not display path tangent as chair yaw.

Export to a new folder. Confirm the CSV contains the entire full-resolution timeline, the metadata identifies the selected window, the CSV hash matches, and COMPLETE exists. Reopen the original recording and confirm it was not changed. Verify cancellation, changed selection, export failure and long-session responsiveness without starting a competing acquisition owner.

## Capture manifest template

Create a new manifest rather than modifying raw recordings. Required columns:

`capture_id, group_id, athlete_code, session_date, remount_id, maneuver_definition, split_role, imu_left_path, imu_right_path, reference_path, sha256_left, sha256_right, sha256_reference, hardware_left, hardware_right, firmware_left, firmware_right, accel_range_left, accel_range_right, gyro_range_left, gyro_range_right, scale_left, scale_right, configured_hz, clock_evidence_path, reference_event_definition, geometry_id, surface_load_notes, reference_qa, input_qa, included, exclusion_reason, operator, reviewer`

Leave unknown fields unknown. A fabricated completion date, range, reference event or passing score is worse than an explicit missing field.
