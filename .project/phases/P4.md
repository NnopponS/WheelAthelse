# P4 conclusion: common offline time, kinematics and quality contract

## Outcome

**Local software work complete. Physical synchronization and model accuracy remain unverified.** The new contract is used by the existing Windows and mobile offline paths. It does not select a P2 candidate or change the model/calibration defaults. P3 remains blocked separately.

The original problem was not only a missing graph. Windows loading discarded device-clock evidence in favor of BLE arrival-relative time, then the adapter rebuilt nominal sequence cadence. The classical runtime computed signed speed and yaw arrays but the adapter returned mainly XY and net yaw. Mobile produced XY only, and its preprocessing could silently substitute problematic timestamps. A shared timeline had to distinguish observable quantities, missing data, recording origin and model identity before displaying coaching statistics.

## Key decisions and their consequences

One output sample corresponds to the center of five aligned 100 Hz input samples. The first result time retains the overlap offset from recording start. A cropped recording beginning later must not appear to begin at time zero. Incomplete tail bins are not fabricated. The estimator is called once for the whole retained session, not once for every display window.

A saved affine clock model reconstructs the recorded mapping; it is not proof of physical sensor simultaneity. The result records the time basis and keeps `physical_sync_verified` false. Legacy time and range assumptions are explicit. No older recording is decoded using the currently connected board's range.

A raw gap exceeding 0.050 seconds fails this analysis path. Short missing intervals may be interpolated and flagged. Duplicates, reorder, rollover and conflicting samples are distinguished. These software-support checks do not weaken acquisition QC or the original optical-reference exclusion gates. Local flags cannot bound accumulated trajectory drift or the reach of a centered/bidirectional model's input contamination.

Windows keeps actual classical `v`, yaw and yaw-rate outputs. The applied zero delay is preserved as zero instead of being replaced through a truthy fallback. XY's first-travel display frame is distinguished from yaw's initial-chair-heading frame. Mobile M4 has no chair orientation output: yaw, yaw rate, signed speed and signed longitudinal acceleration remain null. XY-derived magnitude speed and speed-magnitude change are labeled separately.

Acceleration uses a centered seven-sample local-linear slope on actual time. On the nominal 20 Hz grid, first-to-last support is 0.30 seconds; edge and contaminated stencils are unavailable rather than zero. This is an offline smoothed estimate, not a validated instantaneous peak. No causal live latency is claimed.

## Failures fixed and lessons

Early implementation checks exposed missing timeline fields in an old ONNX test fixture and asynchronous filesystem-test races. The fixture now supplies an explicitly synthetic clock; it does not invent real capture evidence. The export widget test awaits the actual async action through completion, rather than assuming the creation of a COMPLETE filename means all writes and UI updates have finished. Previous failed logs are retained rather than replaced by a generic success statement.

## Remaining limits and next use

The current software can expose a consistent experimental result while refusing unsupported data. It cannot repair missing independent clock/reference evidence by changing a label. Raw-unit provenance, mounting/slip effects, independently measured synchronization and the P3 candidate decision remain separate work. P5/P6 build review controls on this contract; P7 documents the required physical capture.
