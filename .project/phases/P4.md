# P4 conclusion: common offline time, kinematics and quality contract

Updated: 2026-09-08.

## Outcome

**P4 source contract is complete. Physical synchronization and trajectory accuracy remain separate evidence gates.**

The purpose of P4 was to make every later graph/statistic honest: preserve the recording's time origin, carry estimator quantities that actually exist, represent unavailable quantities as unavailable, and make gaps/timing/model identity visible instead of silently fabricating a smooth timeline.

## Original problem

Before P4:
- Windows session loading could discard saved device-clock evidence and rebuild time from BLE arrival/nominal sequence cadence.
- Windows classical inference computed signed speed/yaw arrays internally but exposed mostly XY/net yaw.
- Mobile M4 produced XY only, while preprocessing could silently substitute timing.
- display-window selection risked being confused with a new local trajectory origin.

A common analysis envelope was therefore required before adding coaching UI.

## Contract delivered

A model sample may contain:
- `time_s`
- `x_m`, `y_m`
- `signed_speed_mps`, `speed_mps`
- `longitudinal_accel_mps2`
- `yaw_rad`, `yaw_rate_radps`
- optional lateral/derived quantities where declared
- `quality_flags`

Result-level metadata records model/schema identity, config/hash, geometry, time basis, sample rate, calibration, derivative support, coverage and warnings.

No JSON NaN/Infinity is allowed. Missing quantities use null/unavailable semantics.

## Time semantics

Windows finalized `.waj` loading preserves raw device timestamp/sequence and saved clock/start evidence. Analysis reconstructs a common recording-relative timeline when the saved affine device-to-PC mapping is available. This mapping is the application's timing basis; it is not independent physical-sync proof.

The first 20 Hz model point retains its actual overlap/window-center offset from recording start. A crop beginning later in the recording must not appear to start at time zero.

Duplicate/out-of-order/conflicting samples, `uint32` rollover, clock resets and gaps are handled explicitly. Short bounded interpolation is flagged. Unsupported large gaps fail rather than being plotted as trusted continuous motion.

## Kinematic semantics

Windows classical/PyTorch analysis uses the estimator's own signed speed, yaw and yaw-rate outputs. Chair yaw is never reconstructed from XY tangent.

Acceleration is a supported offline derivative over declared time support; unsupported edge/gap points remain unavailable.

Mobile M4 is still XY-only. It may expose clearly labeled XY-derived speed magnitude/change, but chair yaw/rate and signed forward speed remain unavailable. Reverse path direction is not chair heading.

## Full-session semantics

Inference/preparation yields one complete session result. Cursor/window controls select from that array; they do not rerun the model, reset pose or recompute a local trajectory from zero. Visual decimation does not change source statistics/export.

## Optional center-IMU compatibility

The later three-IMU source continuation extends capture/storage without changing this model contract:

- session loaders may preserve `samples['C']` alongside L/R,
- timing evidence may include C without invalidating the L/R clock contract,
- current trajectory preparation still explicitly selects L and R,
- adding arbitrary C samples must not change the legacy `(T,5,12)` input tensor,
- C remains available for raw preview/export even though current model output ignores it.

This prevents the common enum-expansion bug where a new role silently becomes part of an old tensor or gets decoded as another role.

## Current follow-up verification

Historical P4 completion had its own test counts and evidence. The latest working-tree continuation now additionally verifies:

- mobile full suite: **715/715**, analyzer clean,
- Windows center/journal/sequence/stress focused set: **13/13**,
- bounded Windows suite excluding an unrelated Slalom-v3 path-test defect: **167/167**,
- normal Windows suite: **171 pass / 1 unrelated Slalom-v3 path failure**,
- C cannot contaminate legacy L/R model input.

The older P4 counts remain historical evidence; the current STATUS/HANDOFF are authoritative for latest verification.

## Remaining limits

P4 cannot establish:
- actual L/R/C hardware synchronization,
- correct historical sensor ranges,
- optical-reference correctness,
- physical chair yaw/position accuracy,
- causal real-time latency,
- model generalization.

Those remain P3/P7 responsibilities.

## P4 conclusion

The project now has one consistent offline time/kinematics/QC language across Windows/mobile and an explicit rule for optional C: **capture it faithfully, but do not let it silently change the existing L/R estimator.**
