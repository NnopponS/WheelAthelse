# P8 v1.8.4 Windows stabilization

Updated: 2026-09-25.

## Scope and baseline

Rebuild the Windows application from exact app tag `v1.8.3` while retaining only the requested 3D trajectory view and equal-distance dynamic scaling from the later candidate. Keep the M5/XIAO source identical to the supplied v1.8.3 firmware snapshot (firmware 1.8.2 / BLE protocol 1.8.0). Do not change mobile publication, `BiWheel3D/`, or the locked paper-test cohort.

## Implemented

- Orbitable 3D trajectory plot with distance-preserving XYZ fit; XY-only predictions identify Z as unavailable and the production model default is unchanged.
- Managed CSV import into Results, optional manual date for undated files, and re-export through the existing flow without overwriting files.
- Background CSV writes with progress and success/failure state.
- Per-recording sequence, malformed-packet, host/firmware queue, transport and FIFO counter deltas, with lifetime totals retained in Diagnostics.
- Sanitized Windows/Bluetooth adapter diagnostics; daemon-aware stop-and-close behavior; opt-in, confirmed, WheelAthlete-scoped cleanup for portable and setup flows.

## Software verification

- Windows GUI/acquisition suite: **241 passed, 6 skipped**.
- M5 firmware host tests: **147 passed**; XIAO firmware host tests: **19 passed**.
- PlatformIO M5 and XIAO firmware builds succeeded for left, right and center roles.
- Python compile check and Git whitespace check passed.
- Working-tree project publication hygiene, staged hygiene, Python compile and Git whitespace checks passed. The Inno Setup compiler was unavailable, so the installer script was verified by packaging-layout tests but not compiled.

## Acceptance limits

No physical BLE stress run or cross-computer comparison was possible. This change adds sanitized host/driver diagnostics but does not claim to fix a Windows Bluetooth transport problem. Firmware is unchanged, so any queue/FIFO drops on the reference firmware remain an acceptance failure to record. Trusted signing is still required before distributing Windows binaries; source-only publication is allowed.

## Conclusion

The candidate software changes and firmware builds passed their available checks. Exact-ref publication is still required before treating v1.8.4 as released. Keep cross-computer BLE, hardware stress acceptance, Inno installer compilation, and trusted Windows signing visible as unverified gates.
