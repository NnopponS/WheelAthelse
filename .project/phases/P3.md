# P3 conclusion: model promotion remains blocked by reference data

Updated: 2026-09-08.

## Decision

**Status: `blocked_by_reference_data`. No general estimator is promoted and production defaults remain unchanged.**

P3 has produced useful research candidates and much better understanding of the failure modes, but the project still lacks the independent synchronized moving reference and locked final groups required to claim general model accuracy.

## Evidence inherited from P2

P2 showed that timing/physics choices matter substantially on historical development support. On the same supported optical intervals of 11 eligible development trials, unchanged legacy versus zero-delay diagnostics gave approximately:

- ATE: `0.980574 -> 0.264658 m`
- heading RMSE: `40.114 -> 13.602 deg`
- 1 s RPE: `0.168185 -> 0.104916 m`
- yaw-rate MAE: `22.811 -> 10.820 deg/s`

These values did not establish a production winner. Full-cache counterevidence remained severe: `SL_01` regressed from about `3.593 -> 4.021 m` and `SL_02` remained around `5.850 m` ATE / `8.143 m` endpoint. The smaller supported-subinterval result can hide drift accumulated before that support.

The ideal one-wheel center-mean rule is physically correct in the tested synthetic no-slip case, but raw range/mounting/clock/slip provenance was insufficient to promote it as a universal data correction.

## Experimental PyTorch Residual v1

A C3D-supervised residual BiGRU was trained for explicit research review. Its design is intentionally residual rather than a replacement black box:

1. construct the dual-hub physics baseline,
2. extract L/R window features,
3. predict signed-speed and yaw-rate residuals,
4. integrate the corrected rates to pose.

The selected residual-v1 checkpoint SHA-256 is:

`d838e98e94d5db2e490bf64816e78a35b367ab2d079a54c9d192848973138a45`

Historical grouped validation on longest raw-observation-supported intervals showed macro ATE about `0.165 m` for PyTorch versus `0.284 m` for the zero-delay physics baseline and `0.574 m` for the frozen deployed recipe. Signed-speed MAE was about `0.0445 m/s`; yaw-rate MAE about `5.55 deg/s`. Heading RMSE remained imperfect and long/full-cache Slalom drift was the clearest counterexample.

The Windows runtime reproduced the research residual-v1 rate/XY path to float32-level numerical differences. That establishes software parity, not independent generalization.

Historical `_05` trials had already influenced earlier work and are regression evidence, not a pristine final holdout.

## Slalom failure analysis

The user supplied an important protocol insight: the Slalom begins and ends at the same place and direction, and U-turns follow fixed cone stations. Full GT-vs-model plots showed that a small local yaw waveform/timing error at a turn rotates every later straight segment. Therefore the important failure is not only final net yaw; it is the **shape and timing of yaw rate during repeated turns**.

A diagnostic oracle confirmed this: setting only each turn's net angle to GT was not enough to solve the path, while using the original PyTorch speed with the GT yaw-rate waveform reduced error much more. This means local turn waveform/phase matters.

A separate sync diagnostic also found that `SL_04` showed a substantially larger apparent affine time-scale mismatch than the train Slalom trials. This is a warning not to make a neural network learn reference-clock error as if it were chair dynamics.

## Slalom Course Adapter v1

Course v1 keeps residual-v1 weights frozen and applies only when the condition is explicitly `SL`/`slalom`.

It uses the known fixed-course protocol:
- complete Slalom should end at the starting heading,
- complete Slalom should return to the starting position,
- heading correction is distributed across detected turn events,
- position closure is allowed only when the required signed-speed correction is within a declared guard,
- C3D is never read at inference,
- non-Slalom conditions are exact no-ops.

Formal `SL_04` full-cache result:

| Method | ATE | Heading RMSE | Endpoint |
|---|---:|---:|---:|
| PyTorch v1 raw | 0.7904 m | 21.67 deg | 1.420 m |
| Course v1 | 0.2187 m | 4.53 deg | ~0 m |

The endpoint must be interpreted correctly: near-zero is partly **imposed by the known course closure**, so it is not independent evidence that raw inertial odometry closed the loop.

## Slalom Course v2: rejected

The first v2 attempt used sign-aware turn detection plus per-turn numerical optimization. Exploratory runs appeared to reach much lower ATE, including values around `0.13-0.19 m`.

That apparent gain failed the most important reproducibility gate. The optimizer evaluated float32 integration while a numerical finite-difference solver used tiny perturbations. Derivatives fell into quantization noise; the research path and the Windows app converged to different solutions, and the app often collapsed to the equal-correction solution.

**Decision: v2 is rejected for accuracy claims.** Keep its source/results as negative evidence. Do not quote the best exploratory v2 number as an achieved result.

This is now a durable model-development rule: a candidate must reproduce deterministically through the intended runtime before it can be selected.

## Slalom Calibrated Course v3

V3 was designed to retain the useful protocol structure while removing the unstable optimizer.

### Design

- residual-v1 PyTorch weights remain frozen,
- train-derived small linear yaw-rate residual calibration,
- train-derived small signed-speed residual calibration,
- sign-aware turn detector,
- complete-course detection from the eight-major-turn sign pattern,
- deterministic heading closure,
- guarded residual position closure,
- learned calibration fails safely by being skipped if it exceeds the training envelope,
- no SciPy/numerical optimizer is required at inference,
- C3D is never used at inference,
- non-SL validation conditions are exact no-ops.

Expected eight-major-turn sign sequence:

`[-, +, -, -, +, -, +, +]`

Formal config:
- `BiWheel3D/configs/slalom_calibrated_course_v3.json`
- SHA-256 `30d75e3afad8328e2433c563823a70640586ad98447f8d675f76cdf42de06478`
- historical test evaluated: `false`
- production default: `false`

### Formal SL_04 validation

| Method | ATE | Heading RMSE |
|---|---:|---:|
| raw residual v1 | 0.790368 m | 21.6689 deg |
| course v1 | 0.218728 m | 4.53390 deg |
| **calibrated course v3** | **0.179216 m** | **3.57882 deg** |

V3 correction magnitude on `SL_04` was small relative to the maneuver:
- learned yaw residual RMS about `0.741 deg/s`, max about `2.814 deg/s`,
- learned speed residual RMS about `0.00939 m/s`, max about `0.03272 m/s`,
- final closure speed correction RMS about `0.02745 m/s`, max about `0.04914 m/s`.

`10x5_04`, AR, CR and OWC are exact no-ops in the formal validation because V3 is explicitly Slalom-only.

### Real-session safety behavior

On the user's `SL Trial19 Mook`, the corrected sign-aware detector sees a complete pattern (about 11 detected events / 8 major turns), whereas the older detector merged opposite-sign events and undercounted turns. The learned V3 calibration proposal exceeded its training envelope, so the runtime correctly skipped the learned calibration rather than clipping/forcing it. The declared complete-course closure can still reduce endpoint under its physical correction guard, but the UI must expose that correction magnitude.

This behavior is preferable to silently forcing an out-of-distribution learned correction.

## Optional center IMU decision

The user has now authorized source support for a third chair-center IMU `C` (`0x43`) with +Z pointing down toward the floor. Firmware and both apps can acquire/store/preview/export it.

This does **not** satisfy P3. A center IMU is not absolute position reference and it does not retroactively validate L/R model errors. Current estimators explicitly ignore C. A center-aware model needs new synchronized L/R/C captures with fixed mounting/ranges and valid independent C3D.

## Why P3 is still blocked

The 2026-09-05 Qualisys archive does not solve the reference problem: all 19 audited dynamic C3Ds contain no point trajectories (`POINT.USED=0`). Model-derived pseudo markers are circular and prohibited for training/scoring.

To reopen selection, obtain:
1. complete moving optical wheel/chair reference with verified labels, units, sample rate and residual validity,
2. documented reference-clock mapping to all relevant IMU clocks,
3. actual sensor firmware/range/scale/mounting identity,
4. grouped development/validation captures,
5. a separately locked final participant/day/remount group,
6. coach-approved thresholds frozen before opening final results.

Then select once on validation, freeze source/config/data hashes, run the final group once and report every failure/exclusion.

## Final P3 conclusion

The project has a stronger research estimator and a deterministic Slalom-specific V3 that materially improves `SL_04` validation under a known fixed-course protocol. That is valuable engineering progress, but it is **not yet a general accepted wheelchair odometry model**. Production defaults remain frozen and P3 stays `blocked_by_reference_data`.
