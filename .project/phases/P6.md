# P6 conclusion: mobile contract, review and local export

## Outcome and incomplete gate

**The compatible mobile software work is implemented: shared time/kinematics/QC serialization, native timeline/window review, safe asynchronous integration and local CSV/JSON export.** The existing M4 ONNX remains the on-device default. It runs locally without a PC model server.

**Porting/promoting an accepted classical candidate and validating Android/iOS hardware remain pending.** P3 has not accepted a candidate. This continuation does not label the old M4 network as the newly validated two-hub estimator or silently replace its weights. Common field semantics and feature fixtures are not cross-platform equality of the two estimators.

## What a coach sees now

The full predicted XY path remains visible. The time slider selects an exact source sample; the range slider selects inclusive original-sample boundaries. The path cursor, highlighted window, channel trace and window statistics use the same stored full-session output. Rendering may decimate curves but lookup, statistics and export retain all samples.

For current mobile M4, the review exposes XY-derived speed magnitude and its magnitude-change rate where derivative support exists. Chair yaw, yaw rate, signed forward speed and signed longitudinal acceleration are explicitly unavailable. A zero-length XY path does not establish zero yaw, and reverse path direction does not establish chair heading. Missing derivatives at edges/gaps remain missing.

The directory action reuses the existing native picker abstraction and creates a unique local export folder. Export contains the full timeline, hash/provenance/selected-window metadata and COMPLETE written last. Cancellation does not write files; failures do not mutate original sessions. Long descriptions and uncertainty text are scrollable rather than hidden by fixed-height layouts.

## Implementation

`lib/model/analysis_contract.dart` implements the Python-compatible field/null/derivative/window semantics with immutable metadata and samples. `analysis_timing.dart` validates sequence epochs, missing/duplicate/conflicting samples and saved time support. `trajectory_model.dart` adds the optional analysis envelope and preserves old XY-only parsing, with consistency validation when both representations exist.

`on_device_trajectory_model.dart` keeps the original ONNX graph and feature contract, records the loaded model hash, moves suitable work to isolates, guards concurrent inference, and waits for active work before disposing native resources. The provider checks mounted/generation state around asynchronous preparation and inference so a stale result does not replace the current session.

`lib/widgets/analysis_review.dart` provides native sliders, plot, selected details, window statistics and export status. `trajectory_chart.dart` highlights exact source cursor/window indices. `session_preview_page.dart` integrates the new review without replacing capture/storage ownership. `lib/export/analysis_export.dart` writes the create-only bundle.

## Verification and failures retained

The final full Flutter suite passed **699 tests**. `flutter analyze --no-pub` subsequently reported **no issues**. No dependencies were installed or changed. These checks cover the entire existing test suite, not only new P6 code.

The native host ONNX test executes the existing bundled graph, verifies finite XY, preserves a declared synthetic timeline, confirms a model SHA-256, and requires unavailable chair-yaw/signed-speed fields to remain null. It also checks the concurrent-inference guard and disposal rejection. This is native execution on the Windows test host, not an Android/iOS runtime test.

The export widget regression performs real temporary filesystem writes while mocking only directory selection. It awaits the actual asynchronous action through completion; it checks that all 100 fixture points are exported while metadata identifies a 21-point selected window. A separate cancellation case verifies no export. Small-screen/large-text checks exercise a 320-pixel width and 1.5x text scale without reported layout overflow. A source-widget screenshot is captured separately without installing the app on a phone.

Earlier logs retain the initial failure in an old ONNX fixture missing the new time/flag fields. The fixture was repaired using an explicitly synthetic clock, not by weakening the production contract. Another failed export-widget check observed COMPLETE before its write/close/UI completion; awaiting the real action fixed that test race. Analyzer issues were addressed in the changed files instead of disabling lint rules.

Eleven shared Python/Dart analytical cases compare contract outputs and window statistics. The existing 90-feature fixture remains unchanged. Neither test proves that Windows' classical estimator and mobile's M4 graph predict the same trajectory.

## What remains and why

The selected classical-model port is intentionally not performed without the P3 decision. Android/iOS inference/provider behavior, filesystem permissions, native picker behavior and BLE coexistence must still be exercised on the intended devices in an authorized build/install acceptance task. Host tests and source screenshots are not substitutes.

The new review is usable for explicitly experimental local XY exploration. It must not be advertised as complete athlete motion reconstruction or full mobile chair-yaw analysis. Once a candidate is accepted, preserve this contract and use Python-generated golden fixtures for the actual Dart estimator port, with numerical and runtime parity tested separately.
