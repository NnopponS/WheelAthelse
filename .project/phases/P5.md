# P5 conclusion: Windows offline review, experimental model comparison and export

Updated: 2026-09-08.

## Outcome

**Windows source workflow is implemented for full-session time/window review and explicit research-model comparison. No installed Windows package or production default was changed.**

The MODEL page is an offline research/coaching review tool. It must keep model identity, data provenance and constraint status visible because different options do not have the same semantics.

## Core workflow

For a finalized Windows recording the user can:
1. choose the recording,
2. choose an explicit model,
3. run full-session inference once,
4. scrub exact source time/sample,
5. select a window without resetting pose,
6. inspect XY and available kinematics,
7. export full-resolution timeline + metadata to a new directory.

The XY chart preserves equal axis scale. Render decimation may be used visually, but cursor lookup, statistics and export operate on original result samples.

Unavailable values are shown as unavailable, not zero.

## Research-trial workflow

The source app can open trusted processed `.npz` trials inside the local `BiWheel3D/data` tree for research comparison. When true C3D GT exists, it may be overlaid read-only as a diagnostic trace. C3D overlay is not an inference input and full-cache overlay metrics are not automatically the model-selection score.

The optional local `BiWheel3D` registry is a discovery bridge only; installed/clean app operation must not depend on that separate repository.

## Model choices and status

### Frozen classical

Remains first/default and keeps its inherited behavior/configuration.

### Experimental PyTorch Residual v1

Uses the residual-v1 checkpoint explicitly. The checkpoint remains research-only and is not `current_best`.

### Slalom Course v1

Uses the same residual-v1 network plus fixed-course closure for explicitly labeled Slalom sessions. The result exposes whether heading/position closure ran, raw/constrained endpoint and correction magnitude.

### Slalom Course v2

**Rejected for improvement claims.** Source/results remain audit evidence because exploratory optimizer gains failed deterministic app-runtime reproduction. It should not be presented in the UI as a superior accepted model.

### Slalom Calibrated Course v3

Current deterministic Slalom research candidate. It uses frozen residual-v1 weights, train-derived small linear yaw/speed calibration, sign-aware turn detection and guarded fixed-course closure.

Formal `SL_04` validation:
- raw v1: ATE `0.790368 m`, heading RMSE `21.6689 deg`,
- course v1: `0.218728 m`, `4.53390 deg`,
- calibrated v3: **`0.179216 m`, `3.57882 deg`**.

Historical test remains unopened. Non-SL formal validation conditions are exact no-ops. C3D is never used at inference.

If learned V3 calibration exceeds the declared training envelope, app behavior must fall back/skip that learned calibration and say so. It must not silently clip to a plausible-looking path.

## Important Slalom UI interpretation

A displayed endpoint near zero can be the result of the known course constraint. Therefore the details/UI/export must distinguish:
- raw model endpoint/net yaw,
- learned calibration applied/skipped,
- heading closure applied,
- position closure applied,
- speed/yaw correction RMS/max,
- complete-course detection/pattern.

This is essential for Trial19-like recordings where the protocol correction can be substantial.

## Optional center IMU in Windows

Windows now supports C at the acquisition and review-data level:
- scan/connect/status for C,
- independent sequence metrics,
- saved clock/start evidence,
- journal v2 for sessions containing C,
- live C card/charts,
- saved-session C preview/export.

The model page still intentionally consumes L/R only. A three-sensor session does not become an 18-channel model input automatically.

This is a test-path defect, not a center acquisition/model behavior regression, but the full suite must not be called green until fixed.

## Export behavior

Exports are create-only. Full timeline and metadata must remain internally consistent and include model/time/quality/constraint identity. Original `.waj`, raw CSV and prior exports are not modified.

## P5 conclusion

Windows is now a strong research-review surface for comparing raw L/R estimators and explicitly constrained Slalom variants while also capturing an optional C stream. The next Windows software action is small and concrete: fix the Slalom-v3 test root path, rerun the full suite, and keep production defaults frozen.
